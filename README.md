# RouteOptimizer

Учебное приложение для оптимизации замкнутого маршрута специалиста по обслуживанию компьютерной инфраструктуры. Алгоритм
Литтла (ветви и границы) находит оптимальный маршрут. Интерфейс для самостоятельной проверки преподавателем на настольном компьютере (1280–1920 px), на русском языке, Blazor WebAssembly и MudBlazor,
.NET 10. Все вычисления выполняются в браузере.

## Запуск

Из корня решения в PowerShell:

```powershell
dotnet run --project ".\RouteOptimizer\RouteOptimizer.csproj"
```

Открыть адрес, напечатанный в консоли. Для фиксированного HTTP-адреса:

```powershell
dotnet run --project ".\RouteOptimizer\RouteOptimizer.csproj" --no-launch-profile --urls http://localhost:5180
```

Нужен .NET SDK 10; при первом восстановлении пакетов требуется интернет. Сервер запуска обслуживает статические файлы:
API, база данных и серверные вычисления не используются.

## Возможности

В приложении четыре вкладки:

| Вкладка | Назначение |
|---|---|
| **Матрица стоимостей** | Ручной ввод, названия объектов, начальная вершина, готовые примеры и импорт Excel |
| **Ход решения** | Сохранённые шаги, дерево поиска, редукция матриц, штрафы, включение и исключение дуг, отсечения |
| **Маршрут и статистика** | Маршрут, стоимости переходов, интерактивная схема, границы и показатели поиска |
| **О методе** | Объяснение формул, ветвления, подциклов и доказательства оптимальности |

## Использование

1. Выберите готовый пример и нажмите **«Загрузить пример»** либо задайте собственную матрицу. Доступны учебный пример
   на 6 объектов и воспроизводимые наборы на 4, 6, 8 и 10 объектов с зерном 2026.
2. Задайте количество объектов и начало маршрута. Названия редактируются в строках матрицы. Строка означает,
   откуда выполняется переход, столбец — куда. Активная строка и столбец выделяются.
3. Введите целые стоимости от 0 до 2147483647. Ноль допустим. Для запрета введите **∞** или **-** либо используйте
   кнопку **«Запретить переход»** у выбранной ячейки. Диагональ запрещена всегда. Tab переводит к следующему полю,
   Enter — вниз по столбцу. Ошибки ввода отмечаются в редакторе.
4. **«Рассчитать маршрут»** выполняет поиск автоматически. **«Выполнить шаг»** обрабатывает один узел и открывает его
   разбор. Ручной и автоматический режимы используют одну сессию: расчёт можно продолжить автоматически после шагов.
5. Во вкладке **«Ход решения»** изучите исходную матрицу, редукцию строк и столбцов, минимумы, штрафы и обе ветви.
   Кнопки предыдущего и следующего сохранённого шага просматривают журнал; новые вычисления выполняет
   **«Выполнить шаг»**. Выбор обработанного узла в дереве открывает его подробности.
6. Во вкладке **«Маршрут и статистика»** выберите переход в таблице или стрелку на схеме: они выделяются вместе.
   Под схемой показываются названия объектов и стоимость выбранного перехода. Выбор доступен с клавиатуры;
   у вершин есть подсказки с названиями. Геометрия схемы условная и не задаёт стоимость.
7. **«Остановить»** сохраняет лучший найденный маршрут и достигнутые границы. **«Рассчитать заново»** начинает новый поиск.
   **«Сбросить расчёт»** очищает результаты, сохраняя матрицу. Изменение исходных данных также сбрасывает предыдущий расчёт.

Статусы различают доказанный оптимум, отсутствие допустимого маршрута и остановленный поиск. При остановке
без найденного маршрута приложение не объявляет задачу неразрешимой. Ошибки входных данных показываются отдельно.

Маршрут посещает каждый объект один раз и возвращается в начало. Матрица может быть асимметричной;
время обслуживания считается постоянным и в оптимизацию не входит. Данные готовых примеров условные.

## Импорт Excel

1. Нажмите **«Скачать Excel-шаблон»**. Приложение создаст `.xlsx` с заполненной матрицей и инструкцией справа от неё.
2. На листе **«Лист1»** задайте от 3 до 10 объектов. Названия расположены в первой строке, начиная с B1,
   и в первом столбце, начиная с A2. Соответствующие названия должны совпадать; строки объектов должны идти без пропусков.
3. Заполните стоимости: целые числа от 0 до 2147483647, **∞** или **-** для запрета. Диагональ игнорируется.
   Пустые стоимости и формулы в считываемых ячейках не принимаются.
4. Нажмите **«Загрузить Excel»** и выберите `.xlsx` размером до **1 МБ**. После импорта проверьте данные и выберите
   начальный объект на сайте. Файл не запускает расчёт автоматически.

При ошибке в ячейке сообщение содержит её адрес, например `D3`. Неправильный или повреждённый файл не заменяет
текущую матрицу. Установленный Excel и отправка файла на сервер не требуются: обработка выполняется в браузере.

**Особенность текущего шаблона:** в C2 записано 120 минут, тогда как готовый пример «Инфраструктура» на сайте
содержит 20 минут для этого перехода. Для точного воспроизведения контрольной матрицы ниже замените C2 на 20
или загрузите готовый пример на сайте.

## Чистая архитектура

```text
RouteOptimizer (Presentation, WASM, MudBlazor)
    → RouteOptimizer.Application → RouteOptimizer.Domain
    → RouteOptimizer.Infrastructure → RouteOptimizer.Application
RouteOptimizer.Tests → Application, Domain
```

- **Domain:** неизменяемая задача, матрица затрат и проверенный замкнутый маршрут. Без зависимостей от внешних слоёв.
- **Application:** алгоритм Литтла, пошаговые сессии, снимки вычислений и контракт `IProblemWorkbook` для Excel.
  Изменяемые матрицы и очередь поиска скрыты внутри реализации.
- **Infrastructure:** `ExcelProblemWorkbook`, реализация чтения и создания `.xlsx` через ClosedXML 0.105.0.
- **Presentation:** ввод, проверка формы, отображение шагов и результата, интерактивная SVG-схема,
  выбор и скачивание файлов, браузерный цикл расчёта. Регистрация сервисов — в `Program.cs`.
- **Tests:** проверки Domain и Application без запуска UI.

MudBlazor подключён только в Presentation, ClosedXML — в Infrastructure. Расчётное ядро не зависит от этих библиотек.
MediatR, репозитории и Unit of Work не используются.

## Контрольный пример

Объекты: сервисный центр, административный корпус, учебный корпус, библиотека, лаборатория и склад.

| Из / в |  1 |  2 |  3 |  4 |  5 |  6 |
|--------|---:|---:|---:|---:|---:|---:|
| 1      |  ∞ | 20 | 30 | 10 | 11 | 25 |
| 2      | 15 |  ∞ | 16 |  4 |  2 | 18 |
| 3      |  3 |  5 |  ∞ |  2 |  4 | 14 |
| 4      | 19 |  6 | 18 |  ∞ |  3 |  8 |
| 5      | 16 |  4 |  7 | 16 |  ∞ | 12 |
| 6      | 22 | 10 |  9 |  7 | 13 |  ∞ |

Минимумы строк: 10, 2, 2, 3, 4, 7; затем столбцов: 1, 0, 2, 0, 0, 5. Нижняя оценка корня — **36**. Первая дуга для
ветвления — **3 → 1**, штраф 11, оценки ветвей включения и исключения — 36 и 47.

- Метод Литтла: **1 → 5 → 2 → 4 → 6 → 3 → 1**, **39 минут**.

## Алгоритм и ограничения

Нижняя оценка получается редукцией строк и столбцов. Ветвление выполняется по нулю с максимальным штрафом. Отсутствие
альтернативы означает бесконечный штраф. Равенства разрешаются по индексам вершин; открытые узлы выбираются по
минимальной оценке, затем по порядку создания.

Включение дуги удаляет строку выхода и столбец входа. Для каждой цепочки запрещается замыкание собственного подцикла;
полное замыкание разрешено только после охвата всех вершин. Потомки получают родительскую оценку плюс новую редукцию.
Штраф повторно к оценке не прибавляется. Итоговый маршрут проверяется и оценивается по исходной матрице.

Поиск начинается без верхней оценки. Первый найденный допустимый маршрут задаёт рекорд; далее он обновляется при
улучшении. Отсечение по условию Н ≥ В применяется только после нахождения маршрута, поскольку требуется один оптимальный маршрут.

- 30 секунд активного расчёта, включая подготовку сессии; ожидание между ручными шагами не учитывается.
- До 20 000 открытых узлов. Если добавление потомков превысит лимит, сохраняется родитель: его оценка продолжает
  ограничивать неисследованную область.
- Подробный журнал первых 2 000 обработанных узлов; последующий поиск и статистика продолжаются.
- Суммы в `long`; запрещённые элементы не участвуют в вычитании минимумов.

При остановке оптимальность не объявляется автоматически. Общая нижняя оценка — минимум оценок открытых узлов и
стоимости лучшего допустимого маршрута. Разрыв вычисляется относительно рекорда, а при нулевой стоимости используется
абсолютная разность.

Время расчёта включает подготовку сессии и снимков; не включает отрисовку и ожидание пользователя.

## Проверка

SDK 10 без `global.json` использует VSTest; проект тестов — xUnit 2:

```powershell
dotnet build ".\RouteOptimizer.slnx"
dotnet test ".\RouteOptimizer.Tests\RouteOptimizer.Tests.csproj" --no-restore
```

| Требование                                            | Проверка                                                                                                                                                           |
|-------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Контрольные оценки, маршруты и матрицы                | `TeachingExample_ProducesExpectedBoundsRoutesAndBranches`                                                                                                          |
| Подциклы длиной три                                   | `CheapThreeVertexSubtours_MustNotBecomeTheFinalRoute`                                                                                                              |
| Равные штрафы и оценки                                | `EqualPenaltiesAndBounds_UseVertexAndCreationOrder`                                                                                                                |
| Запреты и отсутствие единого цикла                    | `ForbiddenTransitionsWithoutHamiltonianCycle_AreInfeasible`, `DisconnectedCycles_WithFiniteRowsAndColumns_AreInfeasible`                                           |
| Разреженный ориентированный граф      | `SparseDirectedGraph_FindsOnlyValidCycle`                                                                                                                        |
| Нулевые стоимости и несколько оптимумов               | `EqualCostsAndTies_AreDeterministicAndAllowZero`                                                                                                                   |
| Остановка, новый запуск, одинаковые режимы            | `StopAndRestart_PreserveBoundsAndDoNotShareState`, `BatchesAndSingleSteps_ReturnIdenticalResults`                                                                  |
| Время без ожидания, предел очереди и журнала          | `TimeBudget_CountsActiveCalculationButNotManualIdleTime`, `OpenNodeLimit_RetainsParentAndValidGlobalBound`, `TraceLimit_DoesNotLimitSearchOrExposeMutableMatrices` |
| Независимая проверка оптимума и оценок                | `ExactSearch_MatchesIndependentSubsetDynamicProgramming` — 48 матриц, включая разреженные и нулевые затраты                                                        |
| Экспериментальные матрицы                             | `ExperimentSamples_AreReproducibleAndFinishExactly`                                                                                                                |
| Правила модели, защита входных данных и большие суммы | `DomainTests`                                                                                                                                                      |
| Независимость ядра от UI                              | `InnerAssemblies_ReferenceOnlyInwardAndFrameworkDependencies`                                                                                                      |

Независимый алгоритм динамического программирования используется только в тестах, не в приложении. Полный перебор не
реализован.
